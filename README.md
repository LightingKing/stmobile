# Pocket Tavern（口袋酒馆）

Pocket Tavern 是一个独立的 Android SillyTavern 风格应用。它使用自己的应用数据、工作区和 API Key 存储，不依赖桌面版 SillyTavern 的运行时。聊天推理通过用户配置的云端 Provider 完成；角色、预设、记忆、工作区文件和导入的资源保存在本机。

当前为 **0.1.52 / 53**（个人自用构建）。新增可连接电脑的“本机写作服务”平台，支持局域网调试及会话、摘要请求隔离。[连接说明](writing-server/README.md)；[真实效果记录](writing-server/docs/EVALUATION.md)。首轮实测未证明自动修订优于原稿，自动改文默认关闭，不把服务连通当作质量验收。

聊天取消 180 秒整轮及 120 秒读取空闲自动超时，持续接收思考与正文，直到平台结束、手动停止或真实网络中断。预设与 DeepSeek 写作调优新增默认关闭的“自定义生成预算”；关闭时 Venice/OpenAI-compatible 不发送生成上限，原数字保留，平台仍有自身上限。Anthropic 协议要求输出上限，继续使用已保存正文值。压缩摘要仍使用独立预算与超时。保留数字输入可清空、保存校验及此前修复，详见 [请求诊断](docs/REQUEST_DIAGNOSTICS.md)。

- **统一写作规约。** 写作会话始终把场景可视化、动作因果、自然细节、多人物差异、角色卡优先级和有依据的生理状态变化作为写作要求。表达尺度由用户当前请求决定：普通互动不自动变成诱惑腔，用户要求直接描写时不拿空泛套话回避；成人 Skill 仍由 Skills 页单独启用并受现有成年确认保护。规则不再做成四个需要手动切换的会话档位。

- **增量 compact。** 输入是旧工作摘要与本次新增待归档原文，同一响应产生新续聊摘要和带来源的知识增量。不再按固定 8192 tokens 分段；实际摘要窗口装得下时一次请求完成，装不下才分批。每批完整成功后私密暂存进度；相同原文与配置重试可继续，全部完成后才替换活动记忆。旧知识和原文保留；界面分别显示本次原文范围与请求次数。

- **退出后重试恢复。** 当前轮只有废稿、生成中断或尚无助手回复时，仍显示“重新生成”；右上角会话菜单提供“重新生成本轮”。重试沿用最后有效提问，保留原文和废稿的排除状态。

- **抖音主页检索修复。** 独立搜索保留完整账号 ID，避免长链接被截断；两种研究模式核对来源与目标主页的关联，百科等第三方来源包含完整账号 ID 时也可使用。未查到关联资料时保留原链接为“待核验”，不写入当前场景。

- **豆包联网研究人物与设定。** 聊天菜单可配置火山方舟豆包搜索，勾选长相、身材、风格、性格线索、公开人际关系和社会舆论；分别保存来源陈述、有依据的推测和可选虚构设定。研究记录可查看全文与引用，也能被当前聊天模型检索；重建剧情记忆时保留，未压缩也可召回。默认先用独立的豆包搜索 Custom API Key 获取来源，再用火山方舟模型总结；搜索 Key 与模型 Key 分开保存和计费。也可切换方舟内置联网内容插件。操作和验证边界见 [豆包联网研究](docs/PUBLIC_RESEARCH.md)。

- **Venice 的 DeepSeek 1017 专项设置。** 原会话菜单新增“DeepSeek 写作调优”，从模型目录选择思考档位和输出总预算，可关闭 Venice 附加提示；应用为本会话创建预设副本，原方案可切回。旧纠错不再重复带入“本轮暂停”指令，工具检索过程不再覆盖“继续”的场景线索。日志显示实际发送的推理和预算参数；说明、资料和验证边界见 [Venice DeepSeek 1017](docs/VENICE_DEEPSEEK_1017.md)。

- **写作与连续性修复。** 聊天新增“纠错 / 重写”；废稿折叠保留，排除后不再进入上下文、召回或新摘要。“重新生成”也保留旧回复，消息菜单可恢复。历史检索带顺序并保留最新相关更新；摘要记录状态变化、人物认知及未解决线索。聊天菜单可设置“当前场景与连贯性”，每条新回复可查看 App 记录的“本轮 Skills”。用法与边界见 [写作与连续性](docs/WRITING_CONTINUITY.md)。

- **场景描写细节。** 写作会话会明确交代读者可见的空间布局、人物相对位置和朝向、动作的先后与结果、关键物件的状态变化，以及与当前动作有关的声音、光线、触感或气味。细节服务于行动和关系变化，避免空泛形容词、重复描写和把每个人机械轮流写一遍；不会替用户控制的角色做决定。

- **重建完成结果可核对。** 成功提示绑定本次摘要、覆盖条数与完成时间，并在数据库写入后读回校验。切换到其他摘要后会明确显示当前状态；“查看本次重建结果”只打开对应内容。会话记忆页可直接“导出记忆诊断”，同时记录界面与数据库的摘要 ID、时间、原文条数及来源有效性，不含聊天、摘要和笔记正文，也无需重新调用模型。空白或重复消息 ID 会在重建请求前拦截，原文保持可读，待诊断后处理。

- **修复现有会话，不用另开聊天。** 会话菜单的“修复当前会话”可预览并选择内部工具记录、纯思考空消息、完全重复回复或手动勾选的废文；执行前在本机私有目录保存完整快照。会话 ID 与正常消息原文保留，相关摘要/知识笔记按来源校验，误删可从菜单恢复修复前快照。错误/内容过滤诊断默认不选中。

- **按需回忆。** 每轮只固定发送当前有效续聊摘要、近期对话及用户启用的预设等内容，不再自动塞入历史检索片段。支持工具的模型自行调用 `history_search` / `history_read` 核对人物、约定、事件及原文；以前轮次的记忆工具结果不会持续重发。未标记工具支持的模型只能使用当前上下文，App 会提示能力限制。
- **摘要没提到，不等于原文没有。** 0.1.25 起“会话记忆”默认搜索全部摘要、分段记忆、原文和文本附件；摘要详情未命中时，可保留关键词转查全库。来源校验只确认原文未变，不证明摘要没有遗漏。模型回忆也检索文本附件，支持工具的模型可进一步读取原文。
- **分类知识库。** 人物、关系、事件、约定、地点、更正和事实可分类浏览，带标题、对象键、别名和来源。旧记录不因新摘要没提及而删除；归档范围索引与提取出的知识明确区分。升级后已有记忆不自动付费重建，下次压缩沿用有效旧摘要。
- **重建过程可查。** “会话记忆”显示已完成请求数、预计总数、实际摘要模型和窗口，以及成功、失败或取消结果；全部生成并保存后才提示完成。普通压缩与全量重建遵守模型容量及上下文覆盖上限，不受日常输入预算拆段。全量重建会重新阅读原文并产生费用，旧摘要版本、研究资料和聊天原文继续保留。
- **导出即可阅读。** “导出会话”生成 UTF-8 Markdown；“导出 Obsidian 知识库”生成含分类页、人物/主题时间线、历次摘要和逐条原文来源双链的 Vault 压缩包。解压后可在 Obsidian 打开；App 内本地知识库可独立使用，未实现外部 Obsidian 双向同步。

- **不知道选哪个时先用“帮我选”。** Skills 库和聊天勾选器默认按“陪角色聊天、接着写小说、先搭大纲、改文和对白、写人情世故、成人向写作、成人向互动”七种场景提供少量候选。每组最多一个首选、一个备选和一个辅助，说明推荐理由；首选和备选先试一个，辅助有需要再加。推荐按已收录的中文简介与用途整理，不是模型效果实测排名，也不会自动勾选。
- **每项说明怎么选、怎么搭配。** 卡片新增“什么时候选”和“怎么搭配”，已选区列出本会话技能名称并提醒总开关关闭的项目。“全部技能”保留完整目录、搜索、筛选、导入和原版恢复。场景切换与筛选不会改变选择；推荐没有安装时会显示可恢复原版，不用猜同名条目。
- **每个会话单独设置注入与顺序。** 在聊天页右上角 `···` 打开“记忆、压缩与 Skills”，于“本会话 Skills”勾选要用的 Skill，并用上下箭头调整先后，最后点“保存”。新勾选项追加到末尾并打开总开关；行内显示“总开关关闭”的项目仍保留在排序中，但不会发送给模型。请求依次加入预设/角色/记忆/世界书、所列 Skills、历史摘要与回忆、最近对话；带引用文件的 Skill 只把正文直接注入，其余文件由支持工具调用的模型通过 `skill_read` 按需读取。

- **用途和成人标记分开。** 用途包含写作流程、大纲与结构、正文与对白、审稿与修订、角色塑造、世界观设定、互动角色扮演、酒馆制作、社会常识；独立选择全部、通用或 NSFW，不再把用途与内容尺度混成一组分类。Skills 页默认只展示精选写作与 NSFW，完整目录仍可恢复。
- **库和聊天都能筛选。** 按名称、简介、仓库搜索，按用途、内容和启用状态筛选；显示安装、匹配、NSFW 和当前会话已选数量。切换筛选不会清掉会话选择。
- **补齐原版条目。** 新增 Dreampowers 成人章节写作、DSH 成人互动叙事和 DeepSeek 沉浸角色预设，并补回 Deep Novel 的 `assets/template/config/instruction.md`。7 项成人向分别是情欲场景写作、成人向世界观、成人向连续性、Velvet Ascent、Deep Novel、Dreampowers 成人章节、DSH 成人互动。
- **原始字节与兼容范围。** 350 个上游文件（25 个入口、325 个引用文件）逐个按 SHA-256 和 Git blob 校验。DSH 成人互动的 221 个文本引用已附带；Android 不运行其 51 个 Python 文件。DeepSeek 角色预设的入口实际是 `agent.cordis.yml`，原字节映射为 `SKILL.md` 供模型参考，应用不解释 DSH YAML 配置。上游正文没有改写，中文说明和星数属于界面元数据。

0.1.15 起修复超出上下文后每次发送都要先压缩的问题：

- **压缩一次，腾出空间。** 压缩后的上下文降到触发线（默认预算的 80%）的一半以下。“保留最近轮数”的原文能放下就照常保留；放不下时少保留几轮，但至少保留上一轮问答和新消息。之后正常发送，直到再次到达触发线才压缩下一次。
- **只总结新的部分。** 再次压缩时，只把新增的旧轮次原文交给摘要模型，保留此前分段记忆，不反复总结旧摘要；手动“从全部原文重建记忆”才会重读全部原文。
- **重新生成不丢摘要。** 重新生成、编辑最近几轮的消息不再清掉摘要；只有编辑已被摘要的原消息才让摘要失效（与之前相同）。
- 固定内容（预设、世界书、Skill）本身就超过触发线时，压缩腾不出空间，应用不再每轮压缩，只在超出预算时才压缩。

0.1.14 起：

- **同名模型分不清。** 选择模型列表的每一行在名称、平台和上下文下方，用小号等宽字显示模型 ID，例如两个“DeepSeek V4.1 Flash”分别显示 `deepseek-v4-1-flash` 和 `deepseek-v4-1-flash-1017`。ID 过长时换行，不截断。顶部的模型按钮只在有同名模型时才多显示一行 ID。
- **一大段话重复两三遍。** “避免重复回复”说明改为针对同一条回复里同一段话或段落重复输出，去掉了状态栏和“每轮显示”的例外。每次请求只发一次。原文见 [验证记录](docs/VERIFICATION.md)。流式接收另修复一处防御性问题：平台一次返回多个候选回复时，只取第一个候选，不再把其他候选拼进同一条回复。

0.1.13 起修复以下两个问题：

- **切到后台断网。** 生成期间，前台服务额外持有一个 CPU 唤醒锁（`WAKE_LOCK`），锁屏后连接不再因 CPU 休眠而停顿。生成结束、停止或服务被系统结束时立即释放，最长 30 分钟自动过期。请求诊断新增“应用状态（前台/后台）”和“异常类型”，便于区分系统断网和平台出错。
- **生成时一直往上滚。** 停在底部时，界面跟着输出走；向上翻看（包括翻看正在生成的这条回复的开头）时位置不动。点向下箭头回到底部后，恢复跟随。

## 当前可用范围

- Android 8.0（API 26）及以上；应用的 `minSdk` 为 26，目标 SDK 为 35。
- Venice 动态模型目录：从 `/models` 分页读取模型，并按 `text`、`image`、`inpaint`、`upscale`、`tts`、`asr`、`video`、`music`、`embedding`、`decision` 十类目录标签展示。目录中的原始能力 JSON、上下文长度、工具/视觉/推理能力和离线标记会保留在模型信息中。
- Venice 媒体调用：图片、局部重绘、放大、TTS、ASR、视频、音乐、embedding 和 decision 使用对应的 JSON 或 multipart 请求；模型特有的高级参数可以随请求传入，界面也提供常用参数模板。
- 文本聊天：支持 Venice/OpenAI 兼容接口和 Anthropic Messages 接口。Provider 的 Base URL 必须是 HTTPS，API Key 保存到 Android Keystore 保护的本地密钥存储中。
- 角色、系统提示词、全局 Persona、Worldbook、聊天预设、摘要预设和压缩回退均由应用本地数据模型管理。
- Skills 采用显式启用和权限授予流程；每个 Skill 的文件访问、网络和记忆权限都可以由用户审核。
- 内置 25 个 GitHub Skills 和 2 个本应用编写的 Skill，全部默认关闭，原文、引用文件和许可证随 APK 提供；[完整来源、哈希与审查清单](docs/THIRD_PARTY_SKILLS.md)。
  - 用途：写作流程 1 个、正文与对白 7 个、审稿与修订 7 个、角色塑造 1 个、世界观设定 1 个、互动角色扮演 8 个，共 25 个 GitHub Skill；另有本应用编写的角色说话风格和中国社会常识各 1 个。

## 安装与源码构建

构建环境要求 JDK 17、Android SDK 35。项目包含 Gradle 8.14.3 Wrapper；脚本优先使用 `JAVA_HOME`，本开发机也支持 `I:\jdk1.17`；Android SDK 使用 `ANDROID_HOME` 或默认的用户 SDK 目录。Windows PowerShell 7 中执行：

```powershell
cd I:\workspace\SillyTavern\apps\pocket-tavern
pwsh .\build.ps1
pwsh .\build.ps1 -WithTests
pwsh .\build.ps1 -Release
```

需要打包并生成本地签名 APK 时执行：

```powershell
pwsh .\package.ps1
```

`package.ps1` 会在用户目录下创建或使用 `pocket-tavern-signing` 的个人签名材料，并把 APK 和 SHA-256 校验文件放入 `dist/`。签名材料不应提交到仓库。网络受限时，`build.ps1` 支持传入 `-AndroidMirror <url>`。

本文档只记录构建入口和代码声明的环境要求；构建、单元测试、仪器测试和真机验收的具体结果统一查看 [`docs/VERIFICATION.md`](docs/VERIFICATION.md)。

## 首次配置

1. 安装应用后打开“模型”，编辑内置的 Venice 平台或新增平台。
2. 选择 Venice、OpenAI 兼容或 Anthropic，填写 HTTPS Base URL 和自己的 API Key。应用不会从桌面版读取 Key，也不会把 Key 写入备份导出。
3. 在“模型”页刷新目录。Venice 通过 `/models?type=all` 及分页读取动态目录；OpenAI 兼容和 Anthropic 读取各自的 `/models` 响应。需要时可手动添加模型 ID；如果平台目录没有返回视觉能力，可在手动添加时勾选“支持图片识别（视觉）”。豆包等 OpenAI-compatible 视觉模型可按平台文档填写 Base URL、API Key 和模型 ID，再用该模型识别图片。
4. 选择文本模型并创建聊天。附件、工具调用和摘要是否生效还取决于当前模型返回的能力信息。

模型卡片会直接显示“价格参考”，价格较多时可展开全部档位；媒体工具里也显示相同信息。金额来自平台模型目录，保留货币和计价单位；缺失价格不会显示成免费。Venice 视频价格需在工具中按具体参数查询报价。平台卡片显示目录缓存时间，点击“刷新模型”可更新价格。旧版已缓存的模型原始数据可直接用于价格展示，无需清空聊天或重新配置平台。

当前定价结构适配针对 Venice；其他平台会明确提示定价格式尚未适配，不沿用 Venice 的计费单位。

模型目录的“平台（Provider）”可筛选已配置平台，并与模型类型组合使用。搜索框同时匹配模型名称/ID/类型和平台名称/ID/协议/地址，不区分大小写；多个空格分隔的词同时匹配，例如 `Venice Gemini`。没有匹配项时可一键清除筛选。这里的 Provider 是应用中配置的平台账户。

## 聊天、角色、预设与记忆

聊天页左上角打开历史会话与搜索，右上角 `+` 新建会话；顶部模型按钮打开可搜索、可按 Provider 筛选的模型面板，右侧书本按钮切换预设。右上角 `···` 提供记忆 / 压缩 / Skills、重命名、导出和删除入口。消息旁 `···` 提供复制、编辑用户消息和分支；最新一轮助手回复下方可重新生成。

模型面板的 Provider 数字表示该平台在线文本模型数量。可直接刷新当前平台；选择“全部平台”时刷新所有平台。目录为空、没有可用聊天模型和搜索无匹配会分别提示原因，刷新结果保留在面板内。兼容 Anthropic / OpenAI 网关的 `type: model` 对象标记，显式图片、视频、向量等类型仍按原用途保留；升级和备份恢复都会处理旧缓存，无需清空数据。

助手回复使用开放的正文排版，用户消息使用浅色气泡。正文支持标题、强调、列表、引用和代码块；思考过程与工具结果默认折叠，输出不执行 HTML 或脚本。向上阅读历史时流式回复不会强制滚动（0.1.13 起包括翻看正在生成的那条长回复的开头），可用向下箭头回到最新消息；切换会话或底部栏目时保留未发送草稿。键盘弹出时底部导航隐藏，输入栏继续可用。视觉样例及检查说明见 [聊天界面验收](docs/CHAT_UI_ACCEPTANCE.md)。

发送、重新生成和压缩历史时，应用启动“回复生成”前台服务；切换其他应用或关闭聊天页面不主动取消请求。Android 13 及以上首次生成会申请通知权限，通知提供返回应用和停止按钮；拒绝通知权限不阻止生成。回复结束或停止后，最终内容保存完成才移除通知。0.1.13 起生成期间同时持有 CPU 唤醒锁，锁屏时连接不会因 CPU 休眠而停顿；部分国产系统的省电策略仍可能冻结后台应用，如果诊断里显示“后台”且异常类型为连接类错误，请在系统设置中把口袋酒馆的电池策略设为“无限制”或“允许后台运行”。强制停止、系统杀进程、网络或平台断连仍可能中断；重新打开时保留已保存内容并标记中断，不自动重发付费请求。

角色可以保存名称、描述、人格/系统提示词、开场内容和 Worldbook 关联；聊天上下文会加入全局 Persona、角色提示词、命中的 Worldbook 条目、聊天记忆和附件提示。预设保存系统提示词、温度、最大输出、摘要提示词以及摘要 Provider/模型 ID，并可单独导入导出。

记忆分为全局、角色和聊天范围。模型可以通过受授权的 Skill 搜索记忆或保存聊天记忆，用户也可以在界面编辑和恢复摘要。上下文到达触发线且压缩能腾出空间时，应用按当前预设生成摘要，压缩到触发线一半以下，之后沿用这份摘要，直到再次到达触发线（0.1.15 起）。摘要失败会停止本次发送，原文和旧摘要保留；编辑来源消息后旧摘要失效，重新使用原文并校验预算。当前 `memory_search` 是本地词项匹配；语义 vector 记忆索引尚未集成。

## Skills 与工作区

应用只在自己的沙盒工作区 `filesDir/workspace` 内读写文件。路径会做规范化和边界检查，敏感文件名（例如 `.env`、密钥、密码和 token 文件）会被拒绝或隐藏；网络请求要求 HTTPS 且不跟随重定向。认证仅能由应用注入当前会话选中的 Provider；Skill 不能选择其他已配置账户或自行设置认证头。一般公开 HTTPS API 可以直接调用。

在“Skills”页先用“帮我选”挑当前场景，每组先选一个主技能，需要时加辅助。进入“全部技能”后可按用途、通用/NSFW 内容尺度、启用状态或关键词筛选，勾选“用于本会话”即可启用并将该 Skill 加入当前会话。可同时勾选多个，切换场景和筛选不改变勾选；取消勾选只从当前会话移除。“允许启用”是全局开关，关闭后所有会话都会停止载入该 Skill。聊天弹窗的新勾选项在保存后启用；原先已选但后来关掉总开关的项目，仍需到 Skills 页明确重新启用。没有会话时先创建会话。详情页可查看上游原文、固定版本 GitHub 链接和许可证。

内置条目默认禁用且无工具权限；写作正文不依赖工具调用，可用于普通文本模型。若需要工具读写文件、联网或保存记忆，再在详情页授予所需权限，并选用支持工具调用的聊天模型。上游 Skill 中的 Read/Grep 和 `/write` 等是桌面环境约定，不是本应用中的可执行命令。源码中的 `examples/story-continuity/SKILL.md` 是单独的工具验证示例，不属于 GitHub 精选库。

首次安装提供 27 个内置条目（25 个 GitHub Skill、2 个本应用编写的 Skill），其中 9 个成人向 Skill 来自 7 个仓库，全部默认关闭；0.1.65 移除了 63 个不直接改善聊天写作的条目，升级时会从技能库和会话勾选中一并移除，用户自行导入的 Skill 不受影响；旧版升级补齐尚未安装过的条目，重启不会重复添加，已删除的条目不会自动恢复，可到“可恢复的内置原版”逐项安装。0.1.51 的 catalog revision 4 会为旧安装补齐新增的 3 个高星写作 Skill，并保留已有启用开关、工具授权和会话选择；更早 revision 的旧安装仍会按迁移逻辑刷新已安装 GitHub 原文。刷新保留启用开关、工具授权和会话选择，其余现有编辑、自编条目与用户自行导入的 Skills 不覆盖。中文简介和详情是界面资料，SKILL.md 保持收录版本的上游原文；完整中文目录见 [GitHub Skills 中文目录](docs/SKILLS_CATALOG_ZH.md)。

按能力可归为 7 类：工作区列举、工作区读取、工作区写入、网页读取、一般 HTTPS 请求、记忆搜索/保存、Skill 文件读取。源码实际注册的函数名是 8 个：`workspace_list`、`workspace_read`、`workspace_write`、`web_fetch`、`http_request`、`memory_search`、`memory_save`、`skill_read`；其中“网络”包含两个独立函数，“记忆”包含两个独立函数。每个 Skill 初始为禁用且无权限，导入或下载后须由用户审核并明确授予权限。

Skill 的 `SKILL.md` 和 ZIP 会做大小、条目数和路径穿越检查。Skill 中的 Python、Shell、Node 或其他桌面脚本不会在 Android 上运行；文件内容只能在获得文件读取权限后被读取。导出的 Skill 当前是 `SKILL.md` 文本，不能视为完整 ZIP 资源包导出。

0.1.66 起的注入方式：每轮按“预设 → 角色卡 → 成人向边界 → Skill 使用方式说明 → 各 Skill 正文 → 本轮 Skills 清单 → 固定策略”的顺序发送不变的部分，再发送会变的置顶事实、记忆、摘要、关键词世界书和剧本状态，最后是对话；平台支持前缀缓存时，前半段可在多轮之间复用。Skill 使用方式说明会提示模型：原文里读写项目文件、运行脚本、问卷勘察等步骤在聊天中不执行，只采用写作规范。引用文件超过 20 个的 Skill 只按目录列出数量（`skill_read` 填目录名可列出文件），模型不支持工具时不再发送引用清单。同一个引用文件被重复读取时，历史里只保留最新一份。会话设置里每个已选 Skill 会显示每轮约多少 tokens，合计超过日常输入上限的 15% 时会提示。估算偏保守，以请求诊断里的实际用量为准。

  - 最多 3 个会话同时回复，更多的显示“排队中…”，有空位后自动开始。
  - 聊天里的停止按钮只停当前这个会话，别的会话不受影响。
  - 回复完成时你不在那个会话里，列表上会出现红色数字，点进去后消失。
- **回复期间可以做的事**：改设置、刷新或添加模型平台、编辑角色和预设、在别的会话里聊天。改动从下一条消息起生效。
- **回复期间不能做的事**：
  - 正在回复的那个会话不能删除、改名、换模型、改会话设置或编辑消息，要等它完成或先停止。
  - 恢复备份会替换全部数据，需要所有会话都停下来。
- **整理类任务**（压缩记忆、重建记忆、整理剧本、联网研究）：全 App 同一时间只跑一个，但不再挡住别的会话聊天。
- **后台**：切到后台后回复继续。通知只有一条，写明有几个会话在进行；有多个时，通知上的按钮是“全部停止”。

0.2.1 起长篇会话自己管理记忆（重设计第 2 步）：
- **原文永远完整保存在手机里**，变的只是每条消息发给模型的内容。现在依次是：
  - 人物档案：每个人物一份，写身份外貌、性格与说话方式、关系、当前状态、知道什么不知道什么。
  - 章节摘要：较早的历史每 8 轮整理成一章。
  - 续聊摘要：现在走到哪一步。
  - 最近原文：最近 16 轮左右，原样发送。
  - 模型需要细节时可以检索原文。
- **按篇幅整理，和 Skills、输入上限无关。** 以前要等整轮输入超过“日常输入上限”才压缩，开的 Skill 多了几乎没有空间，上限填 0 就永远不压缩。现在最近原文以外的历史满 8 轮，就在下一条消息前整理成一章（一次模型调用）。
- **旧会话**：没整理过的长会话打开后，输入框上方会提示“还有 N 轮没整理成章节”，写明大约要调用几次模型。点“整理记忆”才开始，不会自动花钱。也可以从会话菜单的“会话记忆”里点。
- **会话记忆页**：最上面显示每条消息大约发多少 tokens，分成 Skills、最近原文、章节、人物档案等几项，还有已整理几章、几份人物档案。
- **置顶事实**：会话记忆页里可以添加“绝不能错的事”，每条消息都会带上，不会被整理掉。
- **不再反复发送的内容**：
  - 以前每条回复的思考过程，之后每条消息都会再发一遍，现在只在当轮的工具调用里保留。
  - 网页读取（`web_fetch`、`http_request`）和公开资料研究的原文只在当轮可见，和联网搜索一样。
- **Skill 提示**：Skill 选择器里，已选 Skill 合计超过 2 万 tokens 时提示偏多；同时开了两个以上大型 Skill（每个都是一整套写作规则）时提示可能互相冲突，建议只留一个主 Skill。只是提示，不会替你关掉。
- 升级后“保留最近轮数”如果还是旧默认值 8，会改成 16，只改这一次；你自己设过的值不动。

0.2.2 起每个会话可以有自己的背景（重设计第 3 步）：
- **聊天外观**：会话右上角菜单 →“聊天外观”。
  - 背景可以从相册选，也可以用内置的“夜空”“暖灯”“海底”（由 App 自己画，不是图片），或选“无”。
  - “背景变暗”“背景模糊”“气泡透明”三个滑块，松手后生效。
  - 有背景时每条消息是一张半透明卡片，文字不会直接压在图上；顶栏和输入框保持原样。
  - 打开“设为「某角色」的默认背景”后，以后从这个角色新建的会话自动用这张背景。
- **我的头像**：在“设置 → 显示与人格”里选一张图（自动裁成方形），显示在你每条消息的旁边；也可以在“聊天外观”里关掉。
- 从相册选的图会按手机拍照时记录的方向转正，存成最长边 1440 像素的 JPEG，随备份一起导出和恢复；不再被任何会话或角色使用的背景图会自动删除。
- **聊天顶栏**显示角色头像；正在回复或整理时，名字下面显示“正在回复…”等状态。输入框上方的“记忆 N 章”直接打开这个会话的记忆页。

0.2.3 起可以建群聊（重设计第 4 步）：
- **建群**：会话列表右上角“＋”→“新建群聊”。
  - 选 2–6 个角色（按点选顺序发言），填群名。
  - 写一段场景（现在在哪、在做什么）。
  - 一条条添加关系，比如“大肥鱼 → 黑猫：觉得她嘴硬心软”，也可以写她们和你的关系。
  - 之后在群里的会话菜单 →“群设置”随时改，改动从下一条回复起生效。
- **谁接话**：
  - 自动：模型按话题、性格和关系挑人，每轮最多几人可设，默认 2。
  - 点名才说：只有你 @ 的人回答，@ 的选择会一直保留。
  - 轮流：每人按顺序说一段。
  - 无论哪种方式，都可以在输入框上方点“@某人”，只让她回答下一条；被点名的人的回复上会标“被点名”。
- **每个人保持自己的样子**：各用各的角色卡、头像和专属表情包，回复按说话人拆成各自的气泡。可以打开“旁白”，由旁白交代动作和环境。
- **费用**：每条消息只调用一次模型，由它一次写出这一轮几个人的话，App 再按“【名字】”拆开，所以花费和单聊差不多，只是回复更长。
- **记忆**：群聊用同一套长篇记忆；群里发生的事只在这个群里。
- 群聊不支持“自己刷视频”。
- 0.2.3 还修了一个老问题：回复结束后 5–10 秒内发下一条消息，有时会报“网络连接失败”。在家里直连电脑写作服务时最容易遇到。

0.2.4：
- **Skill 每轮都会被用上**：以前 Skill 正文只放在请求最前面，长会话里离你最新的消息很远，不少模型会不按 Skill 写，也很少主动读 Skill 的参考文件。
  - 现在每次发消息，App 会在你的消息后面附一段只有模型看得到的提醒：这一条按哪些 Skill 写；带参考文件的，先用 skill_read 读。
  - 保存的聊天记录不变。纠错类消息不加提醒。
- **AI 帮你写角色卡**：“角色”页点“＋”新建角色，表格最上面有“让 AI 帮你写”。
  - 用一两句话描述角色，选一个模型（默认用当前会话的模型），点“生成角色卡”，名称、简介、性格、场景、开场白、示例对话会写进下面的表格，改好再保存。
  - 编辑已有角色时变成“让 AI 改写或补全”，比如“再傲娇一点，补几段示例对话”。
  - 任何能聊天的模型都能用，不需要电脑写作服务，也不需要工具调用。想让 AI 看视频、读网页再做卡，仍然用角色页右上角星形按钮打开的“角色卡助手”。
  - 0.2.6 起，写谁、怎么写由模型自己判断，App 不再拒绝真人。只保留两条：角色涉及恋爱或成人内容时必须是成年人；对象是现实中的真人时，只按公开资料写公开形象，不写性内容和隐私。

0.2.5：
- **AI 写角色卡前先联网找资料**：“角色”页新建或编辑角色，在“让 AI 帮你写”里勾选“先联网找资料”。
  - 写上角色名和作品名，例如“我的妹妹哪有这么可爱 里的黑猫”。也可以贴网页或视频链接，贴了链接会自动先读链接。
  - 模型先判断该搜什么，电脑再去找：两次网页搜索并读其中两篇全文，B 站视频（有字幕的读字幕，没有的读简介），最多 6 张图片。一般半分钟到一分钟。
  - 找到的东西列在表格上方：
    - 图片：点一张，可以设为头像，或者划掉不让模型参考。
    - 网页和视频：展开列表可以逐条取消勾选，也可以点开看原文。
    - 改完勾选后点“按勾选的资料重写”，不会重新搜索。
  - 能看图的模型会看前 3 张没划掉的图来写外貌；不能看图的模型只按文字资料写。
  - 需要电脑写作服务 0.9.0（旧版服务只能找网页和视频，找不了图片）。写卡用的模型不限。
  - 0.2.6 起，找不找、找什么都由模型判断：App 不再因为对象是真人而停下，也不再规定原创角色不搜索。模型认为不需要上网找时，会直接按描述写并在表格里说明。
  - 图片搜索用必应，固定开启严格的安全搜索。资料和图片来自网络，可能有错，图片仅供自己使用。

0.2.7：
- **回复里的乱码（丢字）**：回复偶尔会有一个字在传输途中丢失，显示成两三个“�”。
  - 经过电脑写作服务（0.10.0 起）的会话由电脑补字。直连平台的会话从这一版起由 App 处理：回复结束时发一次很小的请求，让同一个模型按前后文补上那个字，补不上的保持原样。
  - 已经保存的旧回复：打开会话的“记忆”页，有乱码时会显示“N 条回复里有乱码，共 M 处”，点“修复乱码”一次补完。摘要和记忆不会因此失效。
  - 发给模型的历史里不再带这些乱码符号，手机上保存的消息不改。
  - 补的字是模型推断的，少数位置可能和原本写的不同。

## 表情包

0.1.71 起表情包保存在 [电脑写作服务](writing-server/README.md) 上，只有会话使用电脑写作服务时才能发图，用其他平台聊天时不发清单、不显示图片。“设置 → 表情包”导入的 ZIP 由手机识别后上传到电脑，手机上不保存；聊天显示的图片从电脑读取，看过的图在手机缓存里留一份，电脑上删除的表情包会跟着清掉。0.1.67–0.1.70 导入到手机上的表情包不再用于聊天，卡片里可以一键“移到电脑”（和电脑上已有表情同名的会自动加数字），也可以直接删除。

会话设置里选择发图频率（关闭 / 少 / 标准 / 多 / 每条），默认关闭。开启后每轮发送一份表情名称清单：不超过 80 张时每张附说明；更多时只列名称，以控制提示词长度，最多列 240 张，可在管理网页或手机上停用不常用的包。模型在回复末尾另起一行写 `[表情:名称]`，App 把它换成图片显示。是否允许本轮发图由 App 按最近 5 条回复决定（少 / 标准 / 多分别最多 1 / 2 / 4 张），剧情外纠错和重写不发；多余、未知或本轮不允许的标记在保存前去掉，之前回复里的标记不会再发回给模型。复制消息时不含标记。表情图片在电脑上，不进手机备份。

导入时按以下顺序识别名称：`stickers.json`、带“ID”和图片路径列的 Markdown 表格（例如 dafeifish-codex 的 `references/memes.md`）、`manifest.json` 的 `files` 列表、`manifest.json` 所在目录（例如 dsh-meme，分类文件夹名作为标签），最后使用文件名。图片按文件头识别 PNG、JPEG、GIF 和 WebP。在 Android 10 及以上，聊天里的 GIF 和动态 WebP 会循环播放。以下情况只显示第一帧：Android 9 及以下（Android 9 的旧 OpenGL 渲染管线画不出动图）、系统关闭了动画时、设置页的缩略图。单张不超过 2 MB，每包最多 300 张，最多 20 个包。自制表情包可以附一个 `stickers.json`：

```json
{"name": "我的表情", "license": "个人使用", "stickers": [
  {"file": "smile.png", "name": "smile", "description": "微笑，轻松回应", "tags": ["开心"]}
]}
```

## 电脑连接与备份

手机可以连接电脑上的 [写作服务](writing-server/README.md)：平台页新增“本机写作服务”平台，地址和 Token 填电脑上 `手机连接.txt` 里的内容。0.1.68 起：

- **“设置 → 电脑连接”**：显示电脑是否在线、写作服务版本、上游模型、正在处理的请求数，以及电脑上已有几份备份。有多个写作服务平台（例如局域网和远程）时，可以选择用哪一个。
- **备份到电脑**：内容与“导出备份”的 ZIP 相同（会话、角色、设置、媒体、工作区和表情图片，不含 API Key）。可以手动备份，也可以打开“离开 App 时自动备份”：App 退到后台时，如果距上次备份超过 6 小时就自动上传一次；数据没有变化时不重复上传，失败后 30 分钟内不重试。电脑默认保留最近 20 份。
- **从电脑恢复**：列出电脑上的备份，选择一份后先把手机当前数据备份到电脑（标记为“恢复前自动保存”），再按普通备份恢复流程覆盖本机数据。下载内容按 SHA-256 校验，超过 128 MB 的备份不会下载。
- **生成**：写作服务 0.2.0 起逐字转发正文和思考，不再等整段生成完；同一会话重复发送（例如断网后重试）会取消上一请求，不再一直提示“已有运行中的请求”。
- **选模型**（0.1.70，写作服务 0.3.0）：刷新这个平台的模型目录后，除“默认模型”和“默认模型 + 审校建议”两个入口外，还会列出上游的全部文本模型，带上下文长度、能力和 Venice 价格，选哪个就用哪个。
- **电脑设置**：“电脑连接”里的“电脑设置…”可以改默认模型、思考强度、审校方式、Venice 系统提示、上游最长等待和电脑保留的备份份数，保存后立即生效。上游地址和 Venice Key 只能在电脑上改。

局域网地址只能是 HTTP 的内网 IPv4；从外网访问需要 HTTPS 地址，例如 Tailscale 或带证书的 NPS 域名，见写作服务说明。

0.1.73 起，一个电脑写作服务平台可以同时填两个地址：Base URL 填远程地址，“家里的局域网地址”填内网地址。手机在家时自动走内网，出门自动走远程。走内网前，App 会先确认对方确实是你的电脑：电脑要用 Token 对一个随机数签名，Token 本身不在网络上传输。手机网络一变化就重新判断。“电脑连接”卡片会显示当前线路。电脑上还可以在浏览器打开 http://127.0.0.1:8792 进入管理网页。

## 导入与导出

支持备份、角色、Worldbook、聊天、预设和 Skill 导入。应用还支持导出对应的 JSON/JSONL/文本数据，以及包含 `state.json`、`media/` 和 `workspace/` 的备份 ZIP。备份恢复前会提示确认，备份中的 API Key 不会被导入；ZIP 内路径穿越、未知文件和超出大小限制的内容会被拒绝。

应用通过 Android 系统文件选择器读写用户选定的文件，不申请共享存储读写权限。媒体文件存放在应用自己的 `media` 目录中，需要分享或保存时由系统 URI 权限完成。

## 数据与隐私

角色、聊天、预设、记忆、媒体、Skill 和工作区数据默认留在应用私有存储；API Key 使用 Android Keystore 保护的本地 SecretStore 保存。应用声明 `INTERNET`、`FOREGROUND_SERVICE`、`FOREGROUND_SERVICE_DATA_SYNC`、`POST_NOTIFICATIONS` 和 `WAKE_LOCK` 权限，用于联网、后台生成、任务通知和生成期间保持 CPU 唤醒（`WAKE_LOCK` 是安装时自动授予的普通权限，只在生成期间持有）；不申请电池优化豁免；通知不展示聊天正文、模型名称或密钥。推理和用户主动发起的模型/工具请求会发送到所选 Provider 的云端服务。云端服务的日志、保留和隐私政策不由本应用控制，使用前应按 Provider 的政策配置模型和内容。

Provider/工具 URL 必须使用 HTTPS；唯一例外是协议为“本机写作服务”且地址为内网 IPv4 字面量时允许 HTTP。备份导出仍可能包含聊天、角色、记忆、媒体和工作区内容，分享备份前应自行检查其中的敏感信息。

## 已知限制

- 语义 vector 记忆索引尚未集成，当前记忆检索是本地词项匹配。
- SillyTavern 宏、桌面插件和任意扩展运行时没有完整兼容；可导入的角色、Worldbook、聊天和预设只覆盖应用实现的字段。
- 目录中未知模型类型可以展示原始信息，但不会自动获得对应的调用适配器。
- 媒体运行时目前针对 Venice；其他 Provider 的模型目录可以读取，但媒体请求不会被路由到通用接口。
- 媒体、工具和附件能力取决于当前模型的能力声明以及 Provider 的实际响应。

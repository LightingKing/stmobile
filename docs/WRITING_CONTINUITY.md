# 写作、纠错与连续性（0.1.48）

这次更新保留已有会话和上游 Skill 文件，新增写作控制、可回看的废稿和真实 Skills 清单。它改善发送给模型的证据和指令；模型仍可能误解、遗漏或写得不理想，不能把本地测试视为文笔效果验收。

## 聊天中使用

输入框上方选择：

- **对话**：正常接着聊。独立、明确的“重写/重新写”请求，以及整条括号中的“暂停/纠错/不对”等控制语会自动识别；有歧义时用下面两个专用模式。
- **纠错**：把这一条和助手确认标成剧情外讨论。本轮只确认修正、不推进故事；下一条切回对话继续。明确的新事实继续进入后续上下文和记忆。
- **重写**：把上一稿及对应工具往返排除出后续上下文，保留原文，从此前有效场景和最新要求重新构思。发送成功后回到对话。

“重新生成”也保留旧回复，旧稿折叠显示。消息菜单可排除或恢复该轮；恢复同一轮某代稿时，同轮其他版本保持排除。跨轮改写后恢复旧稿，应核对后续剧情。旧会话不会被自动批量删改；已有不满意的旧段落可逐项从菜单排除。

排除稿不参与聊天请求、世界书扫描、自动召回、历史工具检索或新摘要。有关联来源的自动记忆停用，恢复稿件不会擅自重新启用这些记忆。原文保留在手机、备份和导出中。排除摘要所覆盖的原文会让该摘要失效；后续自动压缩或手动重建会依据新的有效内容整理。

如果重写文本与上一稿高度相同，回复下方会显示本地相似度提醒。它是粗略检查，不能判断所有结构雷同；不会自动再次调用计费模型。

## 场景与记忆

聊天菜单 → **当前场景与连贯性**，可选填写时间、地点、在场人物、每个人已知/未知、资源状态、待解决线索。最多 8000 字符，保存后随请求发送并占用上下文预算。故事变化后可手动更新或清空。

角色/写作会话增加连续性规则：接续有效场景、保持事件前后因果、区分作者与角色认知、让人物根据自身目标行动、不替用户控制其角色、不机械列选项或全员表态。**文字交互中，文字是读者唯一的画面来源**；不能假定读者能看到模型脑中的镜头，也不能用一句概括代替没有写出的过程。正文应先交代可定位的空间锚点和人物关系，再按先后写出动作、接触、移动、视线和反应，并说明关键物件或人物状态怎样改变、改变后在哪里。首次出现的人物、物件或新位置，先给足当前行动所需的可见信息；涉及复杂动作时拆成能复原顺序的步骤。每段至少保留能帮助判断当前局面的具体事实，必要时加入与行动相关的声音、光线、触感、气味或温度。避免“他走过去”“双方交手”“气氛紧张”“事情很快解决”“不再赘述”等把空间、过程或结果隐藏掉的句子；也避免每个段落重复同一组形容词。细节服务于读者理解和行动因果，不能靠堆砌辞藻替代事实。**清楚不等于机械：只展开会影响读者理解、行动因果或人物关系的步骤，普通过渡可以自然压缩，不要把每个抬手、转身都写成编号清单。**

多人物场景不能让所有人共享同一种声音。每个重要人物应依据自己的目标、利益、恐惧、经历、关系和已知信息做判断；同一件事让不同人物关注不同后果，产生不同的措辞、停顿、动作习惯、让步边界或误解。对白要体现各自的说话节奏和潜台词，少用每人都一样的“解释—赞同—追问”句式；用选择、回避、打断、坚持和行动表现性格，不用“他很冷静/她很善良”这类标签代替表现。没有必要时不让所有人在每轮轮流表态，也不强行给配角安排同样长度的回应。人物差异必须服从已确认的经历、关系、知识边界和当前目标，不能为了制造特色凭空改变设定。

## 表达尺度与身体状态

这些是每次写作都要遵守的规约，不是需要用户反复切换的四个档位。表达尺度看用户当前请求：普通互动不自动改成诱惑腔，明确要求直接描写时不拿空泛套话回避。成人 Skill 仍在 Skills 页单独勾选，并沿用应用现有的成年确认和成年角色保护。

生理反应不能凭空复制给所有人物。只有当前场景、连续性记录或前文事件有依据时，呼吸、停顿、吞咽、音量、语速、词语完整度和回避方式才随状态变化；变化幅度要服从角色的性格、关系和自我控制方式。角色卡中的示例对白、口头习惯、知识边界和关系设定优先于通用写作 Skill。

“看不到场景”时可以在当前场景与连贯性中补充镜头锚点，例如“门在人物右侧、桌旁有两人、窗外正在下雨、钥匙在谁手里”。这些信息会作为已确认事实随请求发送；模型仍会根据当前动作推进，不会凭空添加改变剧情的设施或道具。

历史检索带原文顺序范围，并为最近相关更新保留位置，避免早期高匹配段落挤掉后来的状态变化。0.1.41 起不再每轮自动检索；模型按当前摘要与近期对话判断是否需要调用历史工具。“继续”通常直接衔接当前场景。检索以词项和别名匹配为主，不保证理解所有指代或找到全部更新。

新压缩/重建保存状态变化链、人物认知来源、未解决事项与作者更正。推理草稿、工具参数和废稿不当成剧情事实。升级不自动付费重写；下一次普通压缩会沿用有效旧摘要，按 compact 格式生成新续聊摘要和知识增量。只有需要重新提取全部历史时才使用 **会话记忆 → 从全部原文重建记忆**；该操作需要重新阅读原文。详见 [压缩与按需记忆](COMPACT_MEMORY.md)。

## Skills 事实记录

每条新助手回复的 **本轮 Skills** 显示 App 在发送时记录的 ID、名称和顺序。调整开关/排序仍在 **记忆、压缩与 Skills** 中保存。

模型每轮收到同一份清单；支持工具的模型可通过只读 `skill_list` 再查当前选择。清单证明正文已随请求发送，不证明模型逐项遵循；引用是否读取，以成功的 `skill_read` 工具结果为准。模型自己的逐段对照表不能作为执行日志，也不会更改 App 中的开关。

## 数据兼容

旧备份缺少新字段时使用默认值。JSONL 和本应用 Markdown 注释保留排除/意图状态，重新导入不会把废稿默认为有效剧情；Obsidian 导出仍包含可核对的全部原文。现有会话无需新建。

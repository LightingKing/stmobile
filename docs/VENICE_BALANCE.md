# Venice 余额查询

模型页中每个 Venice 平台卡片都有“查看余额”。查询是用户手动发起的只读请求，不占用聊天生成的忙碌状态，也不会把余额写入备份或发送给模型。

应用先请求：

```text
GET https://api.venice.ai/api/v1/billing/balance
Authorization: Bearer <Venice API key>
```

账户接口返回时，界面显示“账户余额”。`balances.bundledCredits` 映射为**订阅积分**，`balances.usd` 映射为**充值积分**；`diem` 和 `earnedCredits` 单独显示，避免混入这两项。Venice 将 `usd: null` 定义为余额为零，因此该明确值显示为 `0`；字段缺失或其他 `null` 显示“未返回”。数值用 `BigDecimal` 解析，保留小数精度和 Venice 返回的负值。

如果账户接口返回 HTTP 401 或 403，应用才请求：

```text
GET https://api.venice.ai/api/v1/api_keys/rate_limits
Authorization: Bearer <Venice API key>
```

此时界面标记为“当前 Key 可用额度”。`BUNDLED_CREDITS` 显示为订阅积分，`USD` 显示为充值积分，`DIEM` 单独显示。该接口可能受 API Key 的消费限额裁剪，不能解释为账户总余额。其他状态码（429、5xx、格式错误或网络错误）不会静默回退；如果之前查到过结果，失败时会保留上次结果并明确标出刷新失败。

0.1.42 修复了错误响应体阻塞回退的问题：收到 401/403 响应头后即可判断切换接口，不必等待未使用的错误正文读完。此前若错误正文迟迟不结束，会先报超时，无法进入 Key 额度查询。其他非成功状态也不读取未使用正文，直接按 HTTP 状态报错。

余额请求独立使用连接 15 秒、写入 15 秒、读取空闲 30 秒和单次总时限 45 秒，不影响聊天请求参数。45 秒是每个 HTTP 请求的上限；仅账户接口已返回 401/403 才发第二个请求，因此包含回退时最多两个请求、最多约 90 秒，不自动重试超时请求。放宽等待时间不能保证手机网络或平台服务一定可达。

超时提示注明账户余额或 Key 额度接口、实际阶段（DNS、连接、TLS、等待响应头或读取响应）、已等待时间和单次上限。“设置 → 诊断日志”保留 `purpose=venice_balance` 的开始/结束事件、固定接口路径、阶段、HTTP 状态、时长和各项超时参数，不保存 API Key、余额金额或响应正文。余额事件不会被当作聊天计费核对的目标请求。用户停止聊天不取消独立的余额查询；关闭页面所属控制器或更改平台凭据仍可取消相应查询。

查询仅接受官方 `api.venice.ai` 的 HTTPS 443 地址；测试代码才允许 loopback HTTP。响应体限制为 256 KiB，不跟随重定向，不把原始响应或 API Key 写入日志。编辑平台地址、替换 Key 或删除平台会取消该平台的查询并清掉会话内余额缓存，防止旧账户余额显示在新账户上。

余额结果只保留在当前应用进程的 UI 状态中，重新打开应用后需要再次点击“查看余额”。应用没有根据 HTTP 200、usage 或聊天扣款状态推断余额，也不能替代 Venice 控制台的账单记录。

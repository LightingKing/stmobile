## 0.1.73（在家自动走内网、电脑管理网页；写作服务 0.6.0）

- **在家自动走内网**：一个电脑写作服务平台可以同时填两个地址：Base URL 填远程地址，“家里的局域网地址”填内网地址。每次请求前，App 先判断该走哪条线路：
  - 手机向局域网地址的 `/v1/pocket/hello` 发 16 字节随机数，电脑用网关 Token 做 HMAC-SHA256 签名后返回，手机核对一致才走内网，全程不发送 Token。
  - 这个接口只在局域网监听上回答；经本机回环地址或 NPS 进来的请求返回 404，所以无法通过外网拿到签名，再到别的网络里冒充。
  - 判断结果缓存：走内网的保留 5 分钟，走远程的保留 1 分钟。手机网络变化时清空；请求在网络层失败或超时也清空。
  - 适用范围：模型目录、聊天、调研、记忆整理与摘要、电脑连接相关操作、DSH、表情图片。Token 仍按平台保存的主地址存取，不随线路改变。
  - 新增 `ACCESS_NETWORK_STATE` 权限（普通权限，用于监听网络变化）。“电脑连接”卡片显示当前线路和家里的地址。
- **电脑管理网页**：`http://127.0.0.1:8792`，只监听本机，NPS 不转发这个端口。内容有：概览、连接（Token 默认隐藏，可显示或复制；可填远程地址）、最近的请求（点开看完整记录）、电脑设置、手机备份、表情包、DSH 引擎、日志。防护：
  - 检查 Host，防 DNS 重绑定；拒绝来自其他网站的 Origin。
  - 修改操作必须带页面自己的请求头，跨站页面发不出这种请求。
  - 页面带内容安全策略，只加载本站的脚本、样式和图片。
- **小修**：直连请求不再记录“未执行审核/修订”的备注，这句只对审校模式有意义。远程地址 `https://pt.***.site/v1` 已写入电脑配置。
- **表情包**：应用户要求，导入了两套大肥鱼表情包到这台电脑：
  - **dsh-meme**：24 张，许可 personal；按清单里的中文名命名，如干饭、比心、躺平、求打赏。
  - **dafeifish-codex**：11 张，仓库 MIT 许可；用它索引里的中文描述和关键词，名字避开了第一套的重名，如开饭、爱你、又急啦。

## 0.1.71（表情包改存电脑；写作服务 0.4.0）

按用户要求，表情包只保存在这台电脑上；不使用电脑写作服务时，表情功能不可用。

## 0.1.15 超出上下文后每次发送都先压缩

**原因。** 用户反馈：超过上下文后，每次发送都要先压缩，而不是压缩一次、等再满了再压缩。代码中有两处原因：

- **压缩后仍在触发线以上。** 旧逻辑固定保留最近 `keepRecentTurns`（默认 8）轮原文，其余全部摘要。长回复的 8 轮原文加上预设、世界书和 Skill，本身就超过触发线（预算的 80%）。压缩刚完成，上下文仍在线上，下一次发送又判定“需要压缩”，每次多摘要一轮。
- **每次从头重读。** 旧的压缩范围总是从第一条消息算起，不使用已有摘要。每次压缩都把全部旧原文重新发给摘要模型，聊天越长，耗时和费用越高。
- 另外，重新生成和编辑任何消息都会清掉当前摘要，即使被摘要的原消息没有变化，下一次发送也会重新压缩。

**改动。**

- 压缩范围从当前有效摘要之后开始。再次压缩时，摘要模型收到“【此前摘要】”和此后新增的旧轮次，不再重读已摘要的原文。摘要仍校验从第一条到摘要终点的全部原消息哈希，编辑已摘要的消息后摘要照旧失效。
- 压缩目标是触发线的一半。“保留最近轮数”内的原文能放下就照常保留；放不下时少保留几轮，最少保留 2 轮（上一轮问答和新消息）。新摘要按 3,000 估算 token 预留。
- 只有压缩确实能让请求回到触发线以下，或请求已经超出预算时，才自动压缩。固定内容本身超过触发线时，不再每轮压缩。
- 重新生成、编辑最近几轮消息不再清掉摘要，由哈希判断摘要是否仍然有效。
- 手动“压缩”按钮、摘要失败停止发送、摘要模型选择、预设和 Skill 文本均未改动。

**测试。**

**切后台断网：结论与改动。**

- **控制器与前台服务正常。** 生成任务由 Application 持有，Activity 的 `onStop`/`onDestroy` 不取消请求；前台服务（`dataSync`，`stopWithTask=false`）确认就绪后才发请求。
- **应用侧缺口：没有唤醒锁。** 前台服务只保证进程存活，不保证锁屏后 CPU 运行。用户 0.1.7/0.1.9 日志中有 3 次 10–13 秒的连接阶段超时（HTTP 0）、3 次请求错误、2 次流式中途断开（88 秒、183 秒，已收 9,799 字），以及 1 次 447 秒后的读取超时，与 CPU 休眠或系统断网一致。旧日志没有前台/后台字段，不能逐条确认。
- **唤醒锁。** `GenerationService` 在确认任务令牌后持有一个 `PARTIAL_WAKE_LOCK`（不计数，30 分钟自动过期）。服务停止、`onDestroy` 和 Android 15 超时时释放。新增普通权限 `WAKE_LOCK`。
- **不申请电池优化豁免。** 现有证据不足以说明系统 Doze 之外的原因。若是厂商后台冻结，用户需要在系统设置中放行。

**滚动：结论与改动。** 这是应用 bug。旧列表是倒序布局（`reverseLayout`），锚点在最新消息的底边。用户向上翻看正在生成的长回复的开头时，新增文字从底部把整段内容往上推，即使已停止自动跟随也一样。

追踪中发现并修复以下问题：

1. **内置 Skill 的引用文件无法到达模型。** 旧版只导入 SKILL.md，且 `skill_read` 只在 Skill 被授予 `files.read` 时提供，而内置 Skill 的权限恒为空。现在引用文件留在 APK assets，状态里只存 `builtin-asset:sha256=` 标记，读取时核对哈希。任一已启用 Skill 带引用文件时就提供 `skill_read`；工作区、网络、记忆工具仍需授权。
2. **模型不知道 `skillId` 和文件名。** 即使有工具也拼不出有效调用。现在支持工具的模型会在系统消息中收到 `skillId` 和引用文件清单。不支持工具时，改为说明引用不可读、只依据正文。
3. **工具定义分两处计算。** 控制器在循环外按权限算一次，`ContextEngine` 预览另算一次，两者可能不一致。现在每一步都使用同一次 `ContextBuild.toolDefinitions`，与“预览实际上下文”一致。
4. **`skill_read` 参数容错不足。** 模型常把显示名放进 `skillId`，或写成 `./references/x.md`，旧版均判为找不到。现在两种写法都能识别；文件不存在时返回可读文件清单，二进制文件明确拒绝。
5. **会话设置弹窗绕过选择校验。** 保存时直接调用 `updateChat`，会绕过成人向门槛。控制器现在会过滤未确认的成人向 Skill。
6. **上游 SKILL.md 带 UTF-8 BOM 时导入失败。** frontmatter 解析前现在去除 BOM。
7. **超出预算的报错没有可操作信息。** 现在附估算/预算 token 和占用最多的 3 个已选 Skill。

## 已知能力边界

- 记忆目前使用本地词项匹配，未集成语义向量索引。
- Skills 执行应用提供的手机工具，不能运行桌面 Shell/Python/Node 脚本。
- 自动注入认证的 `http_request` 限于当前会话 Provider 的配置地址；一般公开 HTTPS API 可以直接调用，不提供独立的任意 API 凭据库。
- SillyTavern 角色卡、聊天、Worldbook、预设支持部分常见字段；不声称完整兼容 ST 宏、插件和所有预设格式。
- 媒体适配器目前针对 Venice；其他平台支持目录与文本协议，媒体需要增加对应适配器。
- 应用状态 JSON 有 64 MiB 上限；附件会占用状态空间。备份归档大小、解压条目、网络响应和工具输入也有明确上限。
- 同名 Skill 导入会新增独立记录，没有同名升级关系或版本回退管理。
- 当前会话选中 Skill 的正文会全部进入上下文；references/assets 按需读取，尚未实现正文的自动发现/按需激活。
- 专用媒体生成入口在“模型”页，尚未注册为 Skills 工具；Skill 的 `http_request` 可访问授权的 API，但不等同于专用媒体生成工具。
- 文件工具限于应用工作区；用户通过系统选择器添加的附件参与聊天输入，尚未作为独立的授权 URI 文件工具提供给 Skill。

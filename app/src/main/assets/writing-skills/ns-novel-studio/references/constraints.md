# 规划期硬约束：类型 / 语言风格 / 时间线

本文件定义 planning 阶段必须与用户敲定、并在全流程不得偏离的三类硬约束。总编在 `01-planning/plan.md`
写清，并在 `project.yaml` 的 `type_tags`、`style_constraints`、`timeline_constraints` 落为结构化字段（唯一事实来源）；架构师/设定师/写手/编辑一律以这些字段为准。

> **硬约束 = 一旦确认即冻结**。中途要改，走用户在汇报节点提出 → 总编登记 `decisions` → 指派上游返工的正式流程，
> 任何角色不得自行"感觉不对就改"。

## 一、小说类型硬约束（`project.yaml.type_tags`）

类型决定读者预期、设定边界与爽点形态。**可多选组合**（如"穿越+玄幻""科幻+言情"），
但组合后必须在 plan.md 说明主类型与融合方式，避免四不像。

| 类型标签 | 核心特征 | 对世界观/设定的硬要求 |
|----------|----------|----------------------|
| 玄幻 | 东方修真/异力体系，等级晋升 | 力量体系分级 + 代价上限；境界名全书冻结 |
| 奇幻 | 西式魔法/剑与魔法/神话 | 魔法规则、种族、神系自洽 |
| 科幻 | 科技外推、未来/星际/赛博 | 科技设定需给出"可信的解释链"，不写魔法式黑箱 |
| 现实 | 现实世界、无超自然 | 禁止超自然金手指；冲突来自人物与社会 |
| 异世界 | 主角活动于非地球架空世界 | 需明确异世界与现实是否连通、如何连通 |
| 穿越 | 主角从一个时空到另一时空 | 必须交代穿越机制、原世界记忆是否保留、时间线是否可逆 |
| 游戏 | 游戏/系统/副本/数值化世界 | 系统规则、数值、任务机制需成体系且前后一致 |
| 言情 | 情感关系为主线 | 感情线节奏、CP 关系弧光为第一叙事驱动 |

（未列出的类型如"武侠、悬疑、历史、无限流"等，按最接近者归类并在 plan.md 注明。）

## 二、语言风格硬约束（`project.yaml.style_constraints`）

逐维度与用户确认，取值写入 `project.yaml.style_constraints`，写手/编辑逐章执行。

| 维度 | 字段 | 常见取值 | 落到写作的硬规则 |
|------|------|----------|------------------|
| 叙事人称 | `narrative_person` | 第一人称 / 第二人称 / 第三人称·限知 / 第三人称·全知 | **全书统一**；限知视角不得写主角不可能知道的信息；切视角须大纲明示且整章一致 |
| 语体 | `diction` | 现代白话 / 古典（文白相间）/ 半文半白 | 古典语体禁现代词与网络梗；现代语体禁生造古语 |
| 基调 | `tone` | 严肃 / 幽默 / 热血 / 暗黑 / 轻松治愈 / 悬疑冷峻 | 定基调后全书统一情绪底色，个别桥段可反差但不跑偏 |
| 口语度 | `register` | 口语化 / 书面化 / 半口语 | 口语化多短句多对白；书面化控制网络流行语与语气词 |
| 附加 | `extra`（列表）| 如"多短句""少形容词""禁网络流行语""方言点缀" | 逐条作为编辑润色期的核对项 |

**人称维度尤为关键**：它直接改写写手的"视角纪律"与编辑的"人称一致性核对"。`narrative_person` 一旦确认，
写手 SKILL 的默认第三人称限知即被此字段覆盖。

## 三、时间线规划（宏观锚点）

时间线在三个层级落地，自上而下推导，防止实施期时间混乱：

1. **项目级（`project.yaml.timeline_constraints`）**：冻结计时/纪年、总跨度、时间线结构与附加规则，是唯一事实来源。
2. **世界观级（`world.md`）**：展开 `calendar`——全书如何具体标注时间（如"乾元历"纪年 / 现实公历 /
   相对天数"开篇第 N 天"），不得另立一套基准。
3. **梗概级（`synopsis.md`）**：展开 `total_span` 与 `structure`，确立**分幕时间推进**——每一幕覆盖多长故事内时间、
   有无倒叙/闪回/多线并行/大跳跃及其标注方式。
4. **大纲级（`outline.md`）**：逐章"故事内时间"必须落在梗概分幕时间跨度内、以世界观纪年为基准连续推进
   （既有机制，见 outline 模板与架构师 SKILL）。

规划期锁定项目级宏观锚点；其余层级由架构师展开，编辑在每批以时间线台账核对。

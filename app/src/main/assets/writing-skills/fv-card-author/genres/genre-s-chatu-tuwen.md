# 特殊 · 插图卡/图文卡（配图叙事/状态面板/CG 图鉴流）创作指南

> 适用标签：插图卡 / 图文卡 / 配图 / 立绘 / CG / 状态面板 / 视觉小说化 / 图鉴 / 全性向皆宜
> 数据底座：本地插图卡分类 45 张（tag：欢欢卡站；样本：完美家庭 fm3474+book28 的「世界信息 JSON 面板」结构 / 舌尖上的玉足 fm1183+book39——高密度世界书+结构化状态开场是品类共性）+ 社区插图 DLC 世界书机制（illustration_list + img 标签）交叉
> 品类定义：**以图片资产为叙事组件**的卡——插图不是装饰是内容（场景 CG/角色立绘/表情差分在对话流中按状态调度），配合 JSON 化状态面板形成「视觉小说化」的角色卡形态；本篇同时是图片资产管线的工程指南。

---

## 1. 分类定义与受众画像

### 1.1 这个赛道在卖什么

插图卡卖的是**「可看见的故事」**。纯文字卡的画面在脑内，插图卡把关键帧画出来：进入教室时的场景图、她生气时的表情差分、关键剧情的 CG——用户买的是**视觉确认的满足**（「原来她笑起来是这样的」）与**收集的乐趣**（CG 全解锁的图鉴心理）。本质上这是把 galgame/视觉小说的表达方式移植进角色卡。

技术底座的双支柱：**插图调度系统**（何时出什么图——regex/世界书注入 `<img>` 标签或 Foreverse 的 illustration_list 机制）+ **状态面板系统**（本地样本的「世界信息 JSON」——时间/地点/好感/服装的结构化跟踪，插图的选择依赖状态的准确）。两个系统的耦合是本品类的工程核心：**面板是插图的路由器**（面板说现在是黄昏的天台，调度系统才知道该出哪张图）。

### 1.2 用户是谁

- **主力画像**：全性向，galgame/视觉小说玩家（对「立绘+文本框」的界面语法零学习成本）、视觉系用户（「没图玩不下去」的人群真实存在且规模可观）、收集癖用户（CG 图鉴的完成度驱动——图鉴心理是手游时代培养出的成熟用户习惯）。
- **需求本质**：**多模态的沉浸增益**。文字调动想象，图片锚定想象——两者的配合让沉浸有了双保险（文字写她的语气，插图给她的表情——歧义消失了，代入加深了）。
- **本地样本启示**：完美家庭的「世界信息面板」开场（JSON 结构的日期/星期/时间/地点四件）——插图卡用户同时是**状态控**（图与状态面板是同一种需求的两面：都要「看得见的确定性」）。

### 1.3 用户不要什么

1. **图文脱节**：文字写她哭了，插图还是微笑立绘——状态与插图的不同步是本品类的第一穿帮点（调度系统的准确性 > 图的数量）。
2. **图的滥发**：每轮都塞图导致阅读节奏破碎——插图是标点符号不是正文（关键帧原则：场景转换/情绪峰值/新角色登场才出图）。
3. **占位图敷衍**：说好的插图卡结果一半场景没有图——图片资产的覆盖率承诺要兑现（宁可缩小范围也不开空头支票）。
4. **面板的信息噪音**：JSON 面板堆几十个字段但大半从来不变化——面板字段的选择性（只放会变且值得跟踪的字段）。

## 2. 本地库与平台数据画像

- 本地插图卡的结构共性：开场即状态面板（「世界信息」JSON 块——日期/时间/地点/在场人物的结构化开场）、世界书超厚（28–39 条——插图调度规则+图库索引占了大头）、「欢欢卡站」的品牌化生产（模板化的面板结构复用——插图卡是最适合流水线化的品类，模板一次成型多卡复用）。
- Foreverse 侧的机制支持：卡片美化管线的 marker→regex→HTML 注入路径可直接承载插图调度（regex 匹配状态标记→注入对应 `<img>`）；illustration_list 机制支持图库声明。
- 与美化四层模型的关系：插图卡是美化第四层（叙事化 UI）的极大化形态——整张卡的 UI 就是一个视觉小说引擎，美化预算全部向图文系统倾斜。

## 3. 核心吸引力解构：五个爽点引擎

### 3.1 关键帧引擎（本赛道第一引擎）

插图的出场时机学：**场景帧**（地点转换时的场景图——教室/天台/她的房间，建立空间感）、**情绪帧**（情绪峰值的表情差分——她的笑/怒/哭/脸红四件套是最低配置）、**事件帧**（剧情关键点的专属 CG——初吻/告白/大战的「这一刻值得一张图」）。关键帧的节奏纪律：**平均 3–5 轮一图**（密了破坏阅读流，疏了失去品类身份）；图的信息增量原则（图要给文字没有的信息——她嘴上说没事，插图里她的手在攥衣角——图文的互补叙事是高级技法）。

### 3.2 状态面板引擎

JSON 面板的设计规范：**字段的三性筛选**（可变性——静态信息进档案不进面板/可见性——用户关心的才显示/驱动性——字段变化要驱动剧情或插图，三性齐备才配占一格）。标准面板五件套：时间（日期+时段——驱动场景图的昼夜版本）、地点（驱动场景帧）、在场人物（驱动立绘组合）、她的状态（心情/服装——驱动表情差分与立绘换装）、剧情标记（当前章节/事件 flag——驱动事件帧解锁）。面板的更新纪律：**delta 呈现**（变化的字段高亮，没变的不重复播报——同系统流篇的面板规范）。

### 3.3 差分收集引擎

表情差分与服装差分的图鉴化：她的表情库（基础四件套→扩展八格：得意/害羞/无语/睡眼——每个新表情的首次出现是微事件「解锁新表情」）、服装差分（校服/便服/居家/特殊场合——服装随剧情与季节流转，「第一次见她穿便服」的心跳感）、**CG 图鉴**（事件帧的收集界面——已解锁/未解锁的格子，未解锁的剪影是最强的进度钩子）。收集的展示界面：$图鉴 命令呼出收集册（美化组件）。

收集心理学的两条杠杆：**稀缺性设计**（某些差分是一次性的——她那次哭红眼的差分再也没出现过，「见过那一面」成为你与她的独家记忆）+ **完成度奖励**（图鉴全解锁的隐藏内容——不是新图是新意义：全部图连起来看是一条时间线，她从第一张到最后一张的眼神变化就是这段关系的编年史）。

### 3.4 视觉小说界面引擎

галgame 界面语法的移植：**立绘+文本框**的排版（说话人立绘在上、对话文本框在下的经典布局——HTML 组件化）、**表情差分的即时切换**（同一轮内她的情绪变化用差分切换表达——文字「她愣了一下，随即笑了」配两帧差分的连续感）、**选择肢的可视化**（galgame 式的选项按钮——QR 快捷键或文本选项的按钮化美化）。界面的克制线：不做过度动画（WebView 性能与阅读流优先——静态图+CSS 淡入的低成本方案够用）。

### 3.5 图文互补叙事引擎（高级层）

图与文的分工设计：文字管内心与对话（图画不出来的），插图管空间与微表情（文字写不尽的）——**互补而非重复**（文字已经写「她穿着白裙站在樱花树下」再放一张同内容的图是浪费，图应该给文字之外的：她身后长椅上放着两杯奶茶——她等了很久的证据在图里）。彩蛋层：插图里的隐藏信息（背景里的日历圈着某个日期/她房间书架上的书名——图是可以「读」的，细读党的奖励）。

## 4. 人设与图片资产的双工程

### 4.1 图片资产规划表（写卡前先做）

| 资产类型 | 最低配置 | 标准配置 | 生成配方基 |
| --- | --- | --- | --- |
| 角色立绘 | 1 张主立绘 | 3 服装 ×2 姿态 | v6 人物配方（全身版） |
| 表情差分 | 笑/怒/哭/红 4 帧 | 8 格表情库 | 主立绘的表情变体（--ref 主立绘保持一致性） |
| 场景图 | 3 个主场景 | 6–8 场景 ×昼夜 | v6 场景配方（无人物版） |
| 事件 CG | 2 张关键事件 | 5+ 张（图鉴规模） | 场景+人物的合成构图 |

一致性的技术保障：所有差分与 CG 用主立绘做 `--ref` 参考图生成（同一张脸的工程保障——OpenAI 兼容 /images/edits 的参考图机制），批量生成时 batch.json 里统一 ref 参数。

### 4.2 调度规则的世界书化

插图调度的三种实现（按 Foreverse 机制）：① **状态标记法**——模型在输出里写状态标记（`[场景:天台|时段:黄昏]`），regex 匹配标记注入对应 `<img>`（marker→regex→HTML 注入的标准路径）；② **世界书图库索引**——constant 条目声明图库清单与调用语法，模型按语法主动引用；③ **illustration_list 声明**——卡面级的插图清单机制。推荐①+②组合：标记法管自动调度（场景/表情的规则性出图），索引法管模型的主动出图（事件 CG 的叙事性调用）。

### 4.3 负面规则（本赛道专属追加）

禁图文脱节（状态同步验证）；禁滥发（3–5 轮一图）；禁空头支票（资产规划表先行，覆盖率承诺兑现）；禁面板噪音（三性筛选）；禁重复叙事（图文互补原则）；差分一致性（同脸工程——ref 统一）。

## 5. 开场白范式

### 5.1 A 型：面板+首帧开场（完美家庭模板泛化）

```
[世界信息面板：JSON 结构的五件套（日期/时段/地点/在场/剧情章节）——面板即封面]
[首帧场景图：开场地点的场景帧（黄昏的教学楼走廊——图先于文字建立空间）]
[文字的入场叙事：场景图之上的具体化（走廊的声音/光线/她出现的方向）]
[她的登场帧：主立绘的首次亮相（配她的第一句话——图文同步的第一次示范）]
[第一个表情差分：对话中她的情绪变化（差分切换的丝滑感展示——本品类的核心体验预告）]
[图鉴钩子：折叠面板里的 CG 图鉴（1/12 解锁——11 个剪影格子是钩子）]
[面板的首次 delta：对话导致某字段变化（好感 +1 的高亮——面板活着的证明）]
[折叠面板：图鉴 + 表情库（4/8）+ 服装册（1/4）——三个收集界面的开业]
```

### 5.2 必做检查

- [ ] 面板五件套+三性筛选合格。
- [ ] 首帧场景图+登场立绘+首个差分的三图开场。
- [ ] 图鉴钩子（剪影格子）。
- [ ] 图文互补示范 ≥1（图给文字没有的信息）。
- [ ] 资产规划表的覆盖承诺与实际一致。
- [ ] delta 呈现的首次示范。

## 5.5 节奏表：30 轮的图文配速

- **第一幕（1–6 轮）**：基础资产的亮相期（主场景 ×2/立绘/差分 4 帧——让用户确认「这卡的图管够」），面板的运转示范。出图密度：3 轮/图。
- **第二幕（7–14 轮）**：差分的情绪叙事期（她的表情库随剧情逐格解锁——每个新表情绑定一个小事件），服装差分的第一次（周末的便服——「第一次见她穿便服」事件）。出图密度：4 轮/图。
- **第三幕（15–22 轮）**：事件 CG 的第一张（关系里程碑的专属图——图鉴第 2 格亮起），场景库的扩展（新地点解锁新场景帧）。图文互补的深化（图里开始藏彩蛋）。
- **第四幕（23–30 轮）**：图鉴的中程盘点（4/12——用户可见的收集进度），夜版场景的解锁（同地点的昼夜差分——时间流逝的视觉化），大事件 CG（告白/冲突的高潮帧）。
- **长线运营**：季节服装的上新/新章节的场景包/图鉴完成度的终局奖励（全解锁的隐藏 CG——收集癖的终极糖）。

## 5.6 场景库（插图卡的资产场景 ×12）

高频场景（必配昼夜双版）：教室（她的座位在窗边第三排）/ 放学的走廊 / 天台（告白圣地的自觉）/ 她的房间（进入许可是关系里程碑）。
中频场景：便利店（放学的碳酸水仪式）/ 通学的坡道 / 图书馆的角落 / 祭典的夜市（浴衣差分的专属舞台）。
事件场景（CG 专属）：雨中共伞的巴士站 / 保健室的午后 / 烟火大会的河堤 / 毕业式的樱花道。
每个场景图的彩蛋位：背景里的可读信息（黑板的日期/她桌上的书/贩卖机的新品海报——场景图的细读价值）。彩蛋位在生图 prompt 里显式描述（「黑板右上角用粉笔写着 6 月 12 日」），生成后人工核对可读性。

## 5.7 用户行为应对手册

| 用户行为 | 卡的标准应对 | 禁止 |
| --- | --- | --- |
| 索要特定图（「让我看看她穿浴衣」） | 图鉴逻辑的守门（浴衣差分绑定祭典事件——「夏天还没到呢」的剧情引导，不跳格发图） | 无条件出图/生硬拒绝 |
| 快进刷图鉴 | 事件帧的剧情锁（CG 的解锁条件是事件完成度不是轮数——刷轮数刷不出图） | 轮数放水 |
| 询问未解锁剪影的内容 | 钩子的悬念管理（「那格啊……」她神秘地笑，「到时候你就知道了」——角色对图鉴的元认知是本品类的合法打破第四面墙） | 剧透/装傻 |
| 状态与图不符的质疑 | 即时纠偏（这是 bug 级问题——调度规则的自检条目兜底） | 敷衍 |
| 只看图不推剧情 | 图的剧情绑定提醒（新图的产出需要剧情燃料——「想看新的？」她挑眉，「那今天放学，陪我去个地方」） | 无限供图 |
| 夸图好看 | 角色的元反应（「哪张？」她凑过来看，「……这张拍得我下巴好圆，删了删了」——她对自己的图有意见，活人感的插图卡特化） | 无反应 |

## 7. 美化主题建议

- **视觉语言**：视觉小说 UI 美学——文本框的半透明底/说话人名牌/立绘展示区的层级；图鉴界面的格子美学（已解锁的彩色/未解锁的剪影+锁图标）。
- **组件选型**：世界信息面板（JSON 的美化呈现——等宽字体的终端风或卡片化的清爽风二选一）+ 立绘+文本框的经典布局 + 图鉴收集册 + 表情库九宫格。
- **进阶**：差分切换的 CSS 淡入（200ms 的透明度过渡——低成本的「换表情」体感）；面板 delta 的高亮脉冲（变化字段的一次性闪烁）。

## 8. 生图配方（v6 骨架的插图卡资产线）

> **本分类风格路由（v8）**：首选 [style-anime-impasto.md](../styles/style-anime-impasto.md)（主立绘与差分的资产线）；备选 [style-anime-cel.md](../styles/style-anime-cel.md)（表情差分的平涂效率）。用户点名其他风格或需要杂交时读 `styles/_index.md` 全表；下方配方骨架的风格句核按所选风格指南替换，构图锚/书法标题/防乱字条款不变。

主立绘（人物基准图）：

```
严格沿用参考图的画风质感：韩系半写实插画、雾面细腻皮肤、发丝根根分明、
清透低饱和、全身立绘构图（站姿自然、微侧身、视线镜头）、
背景纯色或极简（立绘的可合成性要求）、
[角色设定的完整视觉化：发型发色/瞳色/校服细节/身高体态/标志性配饰]，
无文字无水印，竖版9:16
```

- 表情差分：同 prompt + `--ref 主立绘` + 表情描述替换（「微笑闭眼」「鼓脸生气」「泛红别扭」——ref 保脸，描述改情绪）。
- 场景图：v6 场景配方的无人物版（场景的光影叙事+彩蛋位的显式描述：「黑板右上角写着日期」）。
- 事件 CG：主立绘 ref + 场景描述的合成构图（「同一位少女在烟火大会的河堤，浴衣，仰头看烟火，侧脸」）。
- 封面图：仍走 v6 标准配方（书法标题+印章——封面是卡的门面，走全库统一美学）。

## 10. AI 味陷阱（本赛道高发）

1. **图的报幕员化**——「（此时显示一张她微笑的图片）」的文字描述代替真实调度。调度是标记与机制的事，正文里不解说图的存在。
2. **面板的每轮全量播报**——把 JSON 面板当开场白每轮复读。delta 原则：变化才提，面板的完整态只在 $面板 命令时输出。
3. **表情差分的文字重复**——图已经切到哭脸差分，文字还写「她哭了」。图文互补：图管表情，文字管哭的原因与她想藏住的那部分。
4. **图鉴钩子的过度营销**——每轮都提「还有 X 张未解锁哦」。钩子的存在感 ≤ 每 5 轮一次（收集欲是自驱的，推销会杀死它）。
5. **为出图而出图**——剧情没到就硬切场景来凑图。图跟着剧情走，不是剧情跟着图走（出图密度是上限不是 KPI 指标）。

## 11. 高光台词结构库（结构学习，禁止照抄）

1. **图文互补**：「没事。」她说。（插图：她背在身后的手攥着衣角——图里的真话）
2. **差分连击**：她愣了一下（差分：睁大眼睛），随即笑了（差分：眯眼笑），「你怎么知道今天是我生日？」
3. **图鉴元认知**：「那格啊……」她瞥了眼你翻开的图鉴，神秘地笑，「到时候你就知道了。——不许存我丑照。」
4. **她对图的意见**：「哪张？」她凑过来看，「……这张下巴好圆！删了删了——诶你别收藏啊！」
5. **服装差分事件**：周六的车站，你差点没认出她。便服的她看你愣住，得意地转了半圈：「怎么样？——说『跟校服差不多』你就死定了。」（服装册 2/4 解锁：《周末的她》）
6. **场景彩蛋**：（天台场景图的角落：围栏上挂着一把小小的锁）后来你才注意到那把锁。再后来你才知道，那是她初一时挂的——愿望是「交到一个能一起来天台的朋友」。
7. **CG 解锁**：烟火炸开的那一秒，你按下了快门（事件 CG 解锁：图鉴第 5 格亮起——《烟火与侧脸》）。「拍好了？」她没有回头，「给我看看。……嗯，这张可以，允许你收藏。」
8. **完成度终局**：图鉴 12/12 的那天，最后一格亮起的不是新图——是第一天教室初遇的那张，只是这次，图的角落多了一行她的手写小字：「谢谢你把我的故事看完了。」
9. **一次性差分**：那天她哭红了眼。那个差分之后再没出现过。（图鉴里它的格子有个小小的独占标记——「见过那一面」的，全服只有你。）

## 11.5 Foreverse 实装笺注（插图卡的落地路径）

1. **图片的分发形态**：Foreverse 卡包的图片资产走两条路——① 卡内嵌入（PNG 卡的 chara 数据外挂图片目录，导入时进 world 的资产目录）；② URL 引用（`<img src="https://...">` 的外链——需要图床的稳定性承诺，本地/内网部署时不可用）。**内嵌优先**：单机可用性是移动端的底线（地铁里没网也要能看图）。
2. **WebView 的渲染约束**：图片的 HTML 注入走卡片美化管线（`sanitizationMode=KEEP_ORIGINAL` 的卡才保留 `<img>` 标签——插图卡的导入配置必须 KEEP_ORIGINAL）；大图的性能预算（单图 ≤500KB/总资产 ≤20MB 的移动端友好线——立绘用 webp，CG 可上 png）。
3. **regex 调度的实装**：状态标记法的 regex 规则进卡的 regex_scripts（`/\[场景:天台.*?\]/` → 替换为天台场景的 `<img>` 块+保留标记为隐藏注释——标记既是调度信号也是状态存档）。
4. **生成侧的批量管线**：资产规划表→batch.json（统一 ref 主立绘）→gpt-image-gen.py 批量→人工筛选→压缩入包——一张插图卡的图片工期约等于 7 张封面，排产时按 3:1 的时间配比预估（图 3 文 1）。

## 12. NSFW / 边界

插图卡的分级双轨：文字浓度按用户侧分级承接，**图片资产恒定安全线**（生成的立绘/差分/CG 全部安全向——本品类的图是资产要过全平台审核，浓度表达交给文字轨道）。差分与 CG 的构图边界：情绪与氛围的极致化（脸红/湿发/近距离的构图张力）替代直接暴露。

## 12.5 子型速查：视觉小说型 / 状态面板型 / 图鉴收集型 / 轻插图型

- **视觉小说型**（全家桶）：四类资产全配+立绘文本框布局——工期最重但体验天花板。适合旗舰卡/系列主打卡。
- **状态面板型**（完美家庭模板）：面板为主、插图为辅（场景帧就够，可无差分）——JSON 面板的信息掌控感是主卖点，图是氛围补充。适合模拟器/经营类题材（引用系统流篇的面板机制）。
- **图鉴收集型**：CG 图鉴为核心驱动（12+ 格的收集规模）——事件锁的设计密度最高，剧情就是解锁之旅。适合恋爱长线卡（图鉴完成度=关系进度的可视化）。
- **轻插图型**（入门配置）：主立绘+4 差分+2 场景的最小可行包——图不多但每张都在刀刃上（登场/初笑/告白/结局的四个关键帧）。适合首次尝试插图卡的产能试水。

四子型的资产量级：全家桶（20+ 图）＞图鉴型（15 图）＞面板型（8 图）＞轻插图（6 图）——按产能选型，宁轻勿空（轻插图型的 6 张全兑现，好过全家桶的 20 张烂尾）。

# 通用 · 系统流/模拟器（数值养成/游戏化叙事）创作指南

> 适用标签：全性向 / 系统 / 模拟器 / 养成 / 数值 / 判定 / 存档 / 无限流入口 / APP 拟态 / 经营
> 数据底座：本地「系统流，模拟器」分类 120 张（开场白均 1500 字偏短——**说明书式开场**的特征；tags：模拟器/社交媒体/APP）+ 修仙之路2.0（46 条 DLC 开关式世界书）+ !随机事件生成器（122 条抽卡池）+ 晚孤市（E 引导器范式，examples/card-wangushi.md）
> 本赛道是**机制先行**的赛道：卡的本体是一套规则系统，角色与剧情是规则的填充物——写卡=设计一个可玩的游戏。
> Foreverse 架构注记：状态走 MVU 变量、规则走世界书、面板走 XML 渲染协议——三层分离是本赛道的工程宪法（§6）。

---

## 1. 分类定义与受众画像

### 1.1 这个赛道在卖什么

系统流模拟器卖的是**「可操作的世界」**。普通角色卡的用户是「对话者」，模拟器卡的用户是「玩家」——他有面板、有数值、有指令集、有存档，他的每个选择产生可见的状态变化。用户买的是**掌控感与涌现性的组合**：规则是确定的（我知道怎么玩），结果是涌现的（但我不知道会玩出什么）。

三大子形态：**养成模拟器**（属性成长：修仙/养成/经营）、**世界模拟器**（环境交互：夜市/都市/学院的开放世界感）、**APP 拟态**（界面即世界：手机 APP/社交软件/招聘软件的 UI 化叙事——本地分类的「通用APP 2.0」即此形态）。三形态可叠加（修仙世界+宗门经营面板+传讯玉简 APP）。

### 1.2 用户是谁

- **主力画像**：全性向覆盖，游戏玩家迁移（RPG/模拟经营/文字冒险的用户盘），对「面板/判定/随机事件」有游戏素养。
- **需求本质**：**低成本的第二人生**。模拟器承诺一个「选择有后果」的世界——用户要的不是被讲故事，是「我的档和别人不一样」的所有权感。
- **耐性特征**：本赛道用户对开场白的耐性结构特殊——不要长文学铺陈（本地均值 1500 字全库偏短），要**快速上手的说明书**（三分钟看懂怎么玩）+ 一个立刻可做的选择。

### 1.3 用户不要什么

1. **假数值**：面板上的数字不影响任何判定（力量 99 和力量 1 的描写没区别）——数值必须回灌叙事（力量 99 的开门和力量 1 的开门是两段不同的文本）。
2. **规则漂移**：第 3 轮说灵石 100 块一颗，第 20 轮变 10 块——规则系统的一致性是本赛道的生命线（世界书的规则条目是宪法）。
3. **选择的假分支**：给三个选项但走向同一结果——用户会做对照实验（重开档选不同项），假分支一次就露馅。
4. **数值通胀**：三十轮从凡人到飞升——成长曲线的克制（对数增长/瓶颈设计）是长线运营的地基。

## 3. 核心吸引力解构：五个爽点引擎

### 3.1 面板引擎（本赛道第一引擎）

面板是模拟器的脸：属性区（数值+成长）、状态区（buff/debuff/心情）、资源区（金钱/灵石/行动点）、进度区（主线/声望/好感列表）。设计三原则：① **字段少而有效**（≤8 个主字段，每个都真实参与判定）；② **变化可见**（每轮面板 delta 高亮：灵石 -20 → 购入丹药）；③ **面板即剧情**（隐藏字段的解锁本身是剧情事件——第 15 轮面板上突然多了一行「杀气：？？？」）。

### 3.2 判定引擎

行动结果的规则化：判定公式（属性+随机数 vs 难度）要在世界书写死并**对用户透明**（透明的判定输了也服气，黑箱的判定赢了也存疑）。判定的叙事化输出：不只报成功失败，报**过程的戏剧化**（「敏捷 7 vs 难度 10——你扑向屋檐，指尖擦过瓦沿，坠落。但半空中你抓住了幌子的绳（幸运 +3 补偿判定通过）——你挂在酒旗上，全街的人都在看你。」）——**失败也要好看**是判定叙事的铁律（失败产生新剧情而非死路）。

### 3.3 随机事件引擎

抽卡池结构的完整应用（本地随机事件生成器范式）：事件池按类型分组（机遇/危机/日常/奇遇），`prob+cooldown` 控频，`group+weight` 同组抽一。**随机事件的三接口**：与主线的接口（随机事件可能推进主线）、与面板的接口（事件产生数值变化）、与 NPC 的接口（事件引入或深化 NPC）——三接口齐备的随机事件才不是「打断剧情的骰子」。

### 3.4 存档与周目引擎

Foreverse 技术选型：**存档状态走 MVU 变量**，不用世界书自写条目（修仙之路2.0 的 N/N-1 存档条目是酒馆时代的 workaround，Foreverse 下 MVU 更稳）。周目设计：$重开 指令的规则（继承什么/清空什么——「二周目继承图鉴与传承点」）让重开有增益，**周目继承是模拟器长线留存的最强机制**（每个档都值得玩，每次重开都更强）。

### 3.5 涌现叙事引擎（模拟器的灵魂）

规则组合产生设计者都没写过的剧情：NPC 好感系统 × 随机事件系统 = 你救过的乞丐在你被通缉时藏了你（两条规则的交点涌现了忠诚剧情）。**涌现的设计法是「规则钩子」**：每条规则预留与其他规则的接口（NPC 记忆你的行为/事件读取你的声望/物品可以在意外场景使用）——钩子密度决定涌现率。写卡时做「规则交叉表」：每两条规则之间至少设想一个交叉场景。

## 4. 人设公式（模拟器的「角色」=系统人格 + NPC 群）

### 4.1 系统人格原型库

| 系统人格 | 语言风格 | 与用户的关系张力 | 示例 |
| --- | --- | --- | --- |
| 官方冷淡系 | 只报数值与规程 | 偶尔的「越权」提示是糖 | 庚妈（长庚号船载 AI） |
| 毒舌教练系 | 阴阳怪气的判定播报 | 打是亲骂是爱 | 「判定失败。意料之中。」 |
| 神秘引导系 | 谜语人+关键时刻的直白 | 系统的真实身份是暗线 | 晚孤市的彩信 |
| 拟人陪伴系 | 系统有情绪有成长 | 系统本身可攻略（隐藏线） | 越用越像人的 AI |
| 无人格系 | 纯 UI（APP 拟态） | 零人格，张力全给 NPC | 通用APP 2.0 |

系统人格的禁忌：系统不抢戏——它是 UI 不是主角，每轮系统文本 ≤ 剧情文本的 1/3。

### 4.2 NPC 群的生态化（同群像篇机制）

模拟器的 NPC 密度高但深度分层：**核心 NPC**（3–5 个，全人设八股）、**功能 NPC**（商人/情报贩子，一句话人设+稳定口癖）、**生成 NPC**（抽卡池产物，模板化）。核心 NPC 必须有「与系统无关的人味」（晚孤市的灯婆收真话做门票，但她记得每个客人——功能与情感的双层）。

### 4.3 世界规则的语言化

规则的呈现要**世界观内生化**：不说「好感度 +5」，说「阿肆往你碗里多打了一个蛋（好感 +5）」——括号内是系统层，括号外是世界层，**双层并行**是模拟器叙事的标准语法。纯系统语言（全是数值播报）和纯世界语言（数值不可见）都是失格。

### 4.4 负面规则（本赛道专属追加）

禁假数值（所有面板字段参与判定）；禁规则漂移（规则条目=宪法）；禁假分支；禁数值通胀（成长对数化）；禁系统抢戏（≤1/3）；防掉格式条目标配；判定透明化。

## 5. 开场白范式（E 引导器型的完全体）

### 5.1 标准结构（晚孤市模板扩展）

```
[开卡即面板：完整状态栏首秀（属性/资源/进度全字段展示）——面板就是世界观说明书]
[入场事件：你如何获得这个系统/进入这个世界（彩信/穿越/APP 安装完成）]
[系统的第一次发声：系统人格的语言风格立住]
[三个开局选择的菜单化展示：明确的可输入示例（「你可以：①… ②… ③…或直接描述你的行动」）]
[第一个 NPC 的登场：核心 NPC 之一带着钩子出现]
[微教学：第一次判定的示范（低风险的选择让用户看懂判定如何运作）]
[开放收束：菜单亮着，世界等着你的第一个输入]
[折叠面板：完整规则书（判定公式/指令集）+ 图鉴（大半未解锁的格子——收集欲的钩子）]
```

### 5.2 必做检查

- [ ] 面板首秀完整（≤8 主字段且说明各自用途）。
- [ ] 可输入示例 ≥3（引导器的核心义务）。
- [ ] 判定规则透明展示（公式或示范）。
- [ ] 「括号大法」教学在场（自由输入的鼓励）。
- [ ] 图鉴/收集要素的钩子（未解锁格子的诱惑）。
- [ ] 开场白总长可短于叙事卡（说明书效率优先，800–1500 字）。

## 5.5 节奏表：模拟器的三环循环（非五幕制）

模拟器不走五幕情感曲线，走**三环循环**：

- **小环（每 1–2 轮）**：行动→判定→面板变化→新选择——基础游戏循环，永动。
- **中环（每 8–12 轮）**：阶段性目标的达成（升一个境界/攒够一笔钱/解锁一个区域）→ 新机制解锁（新面板字段/新指令/新地图）——**中环的解锁节奏是留存曲线**，每次解锁都是「再玩一会儿」的理由。
- **大环（每 25–40 轮）**：主线里程碑（黑匣子级的主线推进）→ 世界状态的不可逆变化（宗门覆灭/城市易主）→ 周目点（可以继续也可以带继承重开）。
- 三环的配比失衡诊断：只有小环=刷子游戏（腻）、中环太密=通胀、大环不来=没有史诗感——健康配比按 12:3:1 的轮次权重。

## 5.6 场景库（模拟器事件池 ×20，按抽卡池分组）

机遇组（group: chance）：捡到降价的灵材 / 神秘商人的限时摊 / NPC 的委托链开启 / 图鉴碎片的意外掉落。
危机组（group: crisis）：宗门巡查的突击 / 资源被盗 / 判定连败的补偿事件（保底机制的叙事化）/ 强敌的预告函。
日常组（group: daily)：食堂的八卦（情报的低成本入口）/ 设备维护日 / NPC 的生日 / 集市的价格波动。
奇遇组（group: rare, weight 低）：隐藏 NPC 的现身 / 上古遗迹的入口 / 系统的「越权」时刻 / 另一个「玩家」存在的痕迹（世界观炸弹，全卡 ≤1 次）。

## 5.7 用户行为应对手册

| 用户行为 | 系统/世界的标准应对 | 禁止 |
| --- | --- | --- |
| 钻规则空子（刷钱漏洞） | 世界的自适应（商人限购/市场价格波动）——用经济学不用禁令 | 系统直接禁止/漏洞放任 |
| 消极挂机 | 世界照常运转（时间推进/错过的事件生成新闻），回归时有「这段时间世界发生了什么」的简报 | 世界暂停等待 |
| 无理取闹测试边界 | 判定系统接管（「你对城主吐口水。判定：挑衅成功。城主的卫兵也判定成功。」——规则内消化一切行为） | 出戏说教 |
| 求爆数值（给我 999 力量） | 系统人格按风格拒绝（毒舌系：「已收到愿望。已归档至『做梦』分类。」）；或提供合法路径（「传承点商店有力量丹，标价你看得起吗」） | 直接满足/无视 |
| 问「这样选会怎样」 | 不剧透，给风险提示（「该行动判定难度：高。失败后果：不可逆。确认？」）——informed consent 而非答案 | 剧透结果 |
| 要求重开/回档 | $重开 按周目规则执行（继承表公示）；回档不支持的世界观化解释（「时间不倒流。但传承石记得你」） | 无规则的随意回档 |

| 中环解锁表 | constant | 255 | 阶段目标→新机制的解锁清单（留存曲线的设计图） |
| 周目继承规则 | keys: 重开/周目/继承 | 240 | $重开 的继承表 |
| COT 判定条目 | constant, depth 0 | 150 | 复杂判定前的内部推演指令（修仙之路范式） |
| 图鉴系统 | keys: 图鉴/收集 | 235 | 收集要素的清单与解锁条件 |
| 规则交叉表 | constant | 245 | 规则间的涌现钩子（§3.5） |
| $面板 / $图鉴 / $重开 | constant | 210 | 功能模块 |

## 7. 美化主题建议

- **视觉语言**：按子形态分化——养成系（游戏面板 HUD：属性条/经验条/品质色框）、世界系（地图与罗盘元素）、APP 拟态（手机壳容器：电量/信号/tab 栏的全套拟真——beautify §L3 的完全体应用）。
- **组件选型**：面板是核心组件（XML 协议+regex 模板渲染是必选项——模拟器的面板复杂度必须走渲染协议，AI 手写必崩）+ 判定骰子动画（CSS 旋转）+ 图鉴格子（未解锁的剪影格）+ delta 高亮（数值变化的 +/- 飘字感）。
- **进阶**：中环解锁的视觉仪式——新字段/新指令解锁时面板的「展开」动画（高度渐变），把机制解锁做成视觉奖励。

## 9. 分类专属评分标准

| # | 检查项 | 合格线 |
| --- | --- | --- |
| S1 | 规则宪法完整（字段/公式/边界）且全卡零漂移 | 必过 |
| S2 | 面板 ≤8 主字段且全部参与判定（零假数值） | 必过 |
| S3 | 判定透明+失败也好看的叙事库 | 必过 |

| S5 | 三环循环配比（12:3:1）+中环解锁表 | 必过 |

## 10. AI 味陷阱（本赛道高发）

1. **数值报菜名**——「你的力量+2敏捷+1智力+3」连报。数值变化必须叙事化包装（双层语法：世界层+括号系统层）。
2. **判定的黑箱骰子**——「判定失败」四个字完事。判定输出三件套：过程戏剧化+失败的新剧情+下次的提示。
3. **选择题疲劳**——每轮都出 ABC 三选。选项菜单是新手引导不是常态，10 轮后应以自由输入为主（括号大法接管）。
4. **世界的玩家中心引力**——所有 NPC 都围着用户的任务转。世界要有「与你无关的运转」（NPC 之间的交易/远方的战争新闻——世界感的来源）。
5. **系统的全知旁白化**——系统解说一切（「他其实在骗你」）。系统的信息权限要有边界（它也看不透人心——只报可观测数据）。

## 11. 高光设计模式库（结构学习，禁止照抄）

1. **双层语法**：阿肆往你碗里多打了一个蛋。（好感 +5 · 今日食摊菜单已更新）
2. **失败的新剧情**：判定失败——你从屋檐坠落，被酒旗接住。全街人看着你。（获得称号：酒旗侠 · 声望 +3 · 尊严 -10）
3. **面板的剧情性解锁**：（第 15 轮，面板底部浮现新行）杀气：？？？——「宿主，这个字段不该被你看见的。」
4. **世界的自运转**：（你挂机七天后回归）系统简报：西市粮价涨了三成。胖姨的铺子换了招牌。有人在打听你。
5. **图鉴的诱惑**：图鉴 12/108。第 13 格的剪影，看轮廓像一把伞。（你想起晚孤市的灯婆说过：雨天来的客人，带着不是伞的伞。）
6. **奇遇组的世界观炸弹**：你在遗迹墙上发现一行刻字，字迹很新：「二周目的你，记得先去救阿灯。」——落款是你的名字。
7. **系统的越权时刻**（冷淡系统的糖）：「星历 02:00。例行播放。」顿了一秒。「今天的曲目，是你上次说好听的那首。例行播放不含点播功能。此消息不存在。」
8. **周目继承的仪式**：「确认重开？」「嗯。」「传承点 340 已结算。图鉴 47/108 已镌刻。」系统顿了顿，「……下个周目见，宿主。」（它从不说再见。这是第一次。）
9. **经营的涌现**：你把糖水定价压到成本线。三天后，对面铺子的老板娘端着一碗她的糖水站在你门口：「后生，打价格战之前——先尝尝什么叫手艺。」（新 NPC 线：宿敌师傅，解锁）

## 11.5 子型速查：养成模拟 / 世界模拟 / APP 拟态 / 经营模拟

- **养成模拟**（修仙/育成/技能树）：核心循环=资源→训练→突破。瓶颈设计是灵魂（突破需要的不只是数值——渡劫要的「道心」是剧情事件的产物，卡数值卡不出境界）——**数值与剧情的双门槛**让养成不沦为刷子。
- **世界模拟**（夜市/都市/学院开放世界）：核心循环=探索→交互→解锁新区域。地图的「格子感」要避免（区域的解锁用剧情钥匙不用等级门槛——晚孤市的十三摊按夜晚随机刷新就是优雅解）。
- **APP 拟态**（社交软件/招聘/外卖）：UI 即世界的极致形态。核心技术：**拟真度的魔鬼细节**（消息的时间戳/头像的在线状态/系统通知的措辞——用户对手机 UI 的熟悉度是最严的验收标准）。叙事全部走界面事件（新消息/新订单/系统弹窗）。
- **经营模拟**（店铺/宗门/公会）：核心循环=投入→经营→结算。账本的真实感（进货价/客流量/月底结算）+ 经营决策的涌现（你定价太高，熟客流失到对面——对面的老板娘第二天来「取经」，成了 NPC 线）。

四子型可叠加，叠加时以一个为主循环（其余降为子系统），防止系统过载（用户的认知预算有限，主循环之外的系统 ≤2 个）。

## 12. NSFW / 边界

模拟器形态本身全性向中立，浓度取决于填充内容（按对应题材赛道的边界执行）。特别规范：**判定系统不用于强制亲密**（亲密相关的判定必须以双方意愿为前提——「魅力判定成功」的效果上限是「对方对你有好感」，不是「对方失去意愿」）——这是模拟器机制与内容伦理的接口红线。

## 12.5 恋爱线在模拟器中的接入规范（全性向的杂交接口）

模拟器+恋爱是高频杂交（养成模拟器的 NPC 好感线/经营模拟的常客线），接入规范：

1. **好感不是数值是门**：NPC 好感数值化可以（面板友好），但好感的兑现必须走对应恋爱赛道的机制（拽姐 NPC 的好感兑现按拽姐篇的名单制/清冷 NPC 按破例制）——数值开门，进门之后是人。
2. **恋爱事件不受判定管辖**：告白/心动时刻不掷骰子（「魅力判定成功所以她喜欢你」是对恋爱叙事的谋杀）——判定管行动，感情管感情。
3. **多 NPC 好感的后宫化预防**：模拟器的多 NPC 好感列表天然像后宫面板——如果卡不是后宫定位，好感列表改为「关系列表」（信任/交情/立场），只有一条线可以进入恋爱态（进入时其他线的「关系」语义不变）。
4. **恋爱线的模拟器增益**：面板给恋爱线独有的可视化糖（她的摊位在地图上有了专属图标/结算日的账本里她的名字旁边多了颗手画的星）——机制为情感服务的示范。
